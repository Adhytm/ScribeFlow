# 前端设计、交互逻辑与修复全景文档

本文档全面梳理 **一键文案撰写工具（v2 全栈版 `copywriter/`）** 的前端设计系统、状态流转逻辑、本次专项审查发现的问题以及已落实的全部修复与验证结果。

---

## 一、前端整体架构与组件职责

前端基于 **React 18 + TypeScript + Vite + Tiptap (ProseMirror)** 构建，采用三栏式沉浸工作台布局：

```
┌────────────────────────────────────────────────────────────────────────┐
│  顶栏 (Header): 品牌标志 · 状态指示胶囊 · 主题切换(系统/浅/深) · 服务商设置 · 停止 │
├───────────────┬───────────────────────────────┬────────────────────────┤
│  左栏 (340px) │  中栏 (主编辑区 / 纸张画布)     │  右栏 (320px)          │
│  GeneratePanel│  EditorPane                   │  Tabs: 修改建议 / 历史  │
│  - 框架选择   │  - 配套标题栏 (带一键复制与反馈) │  - SuggestionPanel     │
│  - 必填项/素材│  - Tiptap 富文本正文          │    (划词局部改写建议)  │
│  - 心智/风格  │  - 划词悬浮工具条 SelectionToolbar│  - HistoryPanel        │
│  - 生成/存版  │  - 实时字数与段落统计条        │    (快照载入/导出/落盘)│
└───────────────┴───────────────────────────────┴────────────────────────┘
```

### 核心模块职责划分

1. **`src/App.tsx`（顶层编排器）**：
   - 持有全局草稿素材（`brief`）、快照历史（`snaps`）、配套标题（`titles`）、改写建议（`sugs`）、服务商配置（`settings`）等核心状态；
   - 驱动流式生成（`generate`）、出标题（`genTitles`）、局部划词改写（`rewrite`）；
   - 协调 ProseMirror 事务（Transaction）与侧边栏建议的接受（`accept`）/ 拒绝（`reject`）；
   - 监听本地文件系统句柄（File System Access API）并触发快照自动写盘。

2. **`src/components/Editor/`（画布交互引擎）**：
   - `Editor.tsx`：承载 Tiptap 编辑器实例，计算视口选区坐标与悬浮工具条出现时机；显示底部实时字数、段落数、预估阅读时间；
   - `SelectionToolbar.tsx`：用户在正文中高亮划词后弹出的浮动工具条，提供快捷改写指令 Chip（更口语、更利落等）与自定义要求输入框；
   - `SuggestionPanel.tsx`：侧边栏 Diff 卡片展示，对比原文与改写结果，支持展开全文、单项/全部接受或拒绝；
   - `suggestionPlugin.ts`：ProseMirror 自定义插件，负责通过 `tr.mapping` 追踪文档坐标重映射，确保在多次插入、编辑后建议坐标依然精准。

3. **`src/components/GeneratePanel/`（文案控制台）**：
   - `GeneratePanel.tsx`：提供 6 大文案框架预设（电商详情、小红书种草、短视频口播、私域朋友圈、硬核测评、爆款单页），多维度素材输入与心智模式选择；
   - `ApiSettings.tsx`：服务商切换与连通性测试模态框，内置各大主流厂商预设及端点探针。

4. **`src/components/History/`（快照与自动落盘）**：
   - `HistoryPanel.tsx`：快照列表回溯、单版本 Markdown 导出、合集全量打包、以及本地目录绑定与自动落盘状态栏。

5. **`src/services/`（通信与存储层）**：
   - `llm.ts`：前端请求中继与 SSE 流式事件解析、分段切分与 HTML 转换器；
   - `storage.ts`：`localStorage` 本地缓存持久化与 File System Access 本地文件写入。

## 二、本次专项审查发现的硬伤缺陷与修复清单

经过对代码与边界条件的严格推演，共发现并彻底修复了以下 6 项核心缺陷与 4 项体验优化：

### 1. 【高危修复】长文向下滚动时划词工具条飞出屏幕外
- **原问题**：工具条位置判断采用 `sel.top < 110`，但 `sel.top` 算的是相对于整篇文档纸张顶部的绝对坐标，混淆了「视口坐标」与「文档容器坐标」。当长文向下滚动后，选区处于视口上方时，计算结果把工具条推到了负视口高度，直接被吸进顶栏上方看不见。
- **修复方案**：在 `EditorPane.tsx` 中引入视口感知机制 `minClientTop = Math.min(start.top, end.top)`，当选区距离视口顶端 `< 160px` 时，工具条自动改放选区下方（`below = true`），其余情况放选区上方，任何滚动深度下均精准可见。

### 2. 【高危修复】模型输出未带 `###` 时正文被清空变白板
- **原问题**：`llm.ts` 的 `parseSections` 与 `sectionsToHtml` 假设模型必定以 `###` 开头，且只保留有 `body` 的段落。一旦模型输出纯文本或格式稍微偏离，`filter(p => p.body)` 把全部内容过滤掉，返回空字符串，导致编辑器直接被刷成一片空白。
- **修复方案**：重构 `parseSections` 与 `sectionsToHtml`：
  1. 正则检测是否存在 `#{2,4}\s+`，若无标题直接按纯文本段落整体安全保留；
  2. 若模型在第一个标题前输出了引导词/引言，提取为前置正文；
  3. 流式阶段如果只有标题尚未输出正文，提前渲染 `<h2>` 占位，绝不吞没内容。

### 3. 【交互修复】按 `Escape` 键无法关闭划词工具条
- **原问题**：在工具条输入框按 Esc 触发 `onClose` 时，仅执行了 `setSel(null)` 然后调用 `editor.commands.focus()`；因为此时编辑器选区仍未折叠，聚焦触发的 `transaction` 再次检测到非空选区，瞬间把工具条又弹了起来。
- **修复方案**：`onClose` 时显式调用 `editor.commands.setTextSelection(to)` 将光标折叠至选区末尾，并增加全局 `mousedown` 监听，点击编辑器外部时平稳关闭工具条。

### 4. 【流程修复】文件夹自动落盘刷新页面后变死状态
- **原问题**：浏览器 File System Access API 的句柄出于安全策略无法以字符串存入 `localStorage`，页面刷新后虽然显示目录名 `(需重新授权)`，但界面只有一个「解绑」按钮，无法一键重新授权。
- **修复方案**：`HistoryPanel.tsx` 增加 `isDirAuthorized` 状态判断，当已选目录但未授权时，醒目高亮「点击授权」按钮，点击直接调起选择器快速续接落盘。

### 5. 【数据安全】历史版本「清空」与「删除」增加防误触二次确认
- **原问题**：点击「清空」按钮会在毫无确认弹窗的情况下，一秒内蒸发用户全部 60 个历史快照。
- **修复方案**：接入 `window.confirm` 安全防线，明确提示清空影响并建议先备份；单版本删除同样增加确认。

### 6. 【业务逻辑】载入快照时同步回滚素材，防止上下文张冠李戴
- **原问题**：载入旧快照只恢复了正文，左侧表单的产品名和人群依然停留在当前输入。如果写完产品 A 接着写产品 B，此时切回 A 的历史版本再点改写，AI 会用产品 B 的素材去改写产品 A 的正文。
- **修复方案**：`loadSnapshot` 同步将快照内保存的 `product` 与 `crowd` 回写至 `brief` 表单，保持正文与素材 100% 同步。

### 7. 【体验优化】补齐编辑器实时字数与段落统计
- 在编辑纸张右下角增加轻量优雅的统计状态栏：实时展示「正文共 X 字 · Y 个段落 · 约 Z 分钟阅读」，满足文案写手对字数容量的核心把控需求。

### 8. 【体验优化】配套标题草稿持久化与一键复制反馈
- 修复刷新页面后当前生成的 5 条配套标题丢失的问题，持久化存入 `cw.titles`；
- 点击「复制」标题按钮，按钮即时变为「已复制 ✓」并保持 2 秒，同时在顶部状态胶囊提示。

### 9. 【视觉优化】改写建议卡片超长原文支持展开/收起
- 解决 CSS `max-height: 72px` 把长原文强行截断的问题，当字数较多时提供「展开全文 ▾ / 收起原文 ▴」切换按钮。

### 10. 【兼容优化】服务商配置内置真实官方主流模型
- 在保留测试预设的同时，为 OpenAI、Claude、DeepSeek、通义千问、Kimi、GLM、Gemini 补全现网真实推荐模型（如 `gpt-4o`、`deepseek-chat`、`claude-3-5-sonnet-20241022`、`qwen-plus` 等），用户填入自备 Key 后开箱即用，不再出现 `model_not_found` 报错。

## 四、写手使用与操作建议

1. **新建与日常创作**：
   - 在左栏选择文案框架（如小红书、电商详情），只需填写「产品名称」与「目标人群」即可点击「生成文案」；
   - 编辑器下方会实时更新字数与段落数。
2. **局部改写（Canvas 交互）**：
   - 在正文中使用鼠标划选任意一句话或一段文字，工具条会自动根据视口空间智能出现在文字上方或下方；
   - 点击快捷指令（如“更短更利落”）或手动输入要求后点击“改写”；
   - 右侧“修改建议”栏会实时生成预览卡片，点击卡片可平滑滚动定位正文，确认满意后点“接受”即可精准无损替换。
3. **重要草稿存盘与版本回溯**：
   - 点击右侧栏的「绑定文件夹」，选择本地任意目录（如 Obsidian 文档库），后续所有生成、改写和存版都会自动以标准 Markdown 格式实时落盘备份；
   - 刷新页面后，若显示 `(待授权)`，点击一次「点击授权」即可恢复自动写盘。
